# Spec: 미니 방명록

> 상태: ready-for-agent · 용어는 [CONTEXT.md](../CONTEXT.md), 결정 기록은 [docs/adr/](./adr/) 참조

## Problem Statement

방문자가 회원가입이나 로그인 없이 가볍게 인사를 남길 수 있는 공간이 필요하다. 하지만 계정이 없으면 "이 **글**을 쓴 사람이 누구인지" 확인할 방법이 없어서, 아무나 남의 글을 고치거나 지울 수 있게 된다. 또한 남의 글의 **비밀번호**를 반복해서 추측하는 것도 막아야 한다.

## Solution

한 페이지짜리 방명록이다. 누구나 **작성자 이름**, **메시지**, **비밀번호**를 입력해 글을 남기고, 모든 글이 **작성 시각** 최신순으로 보인다. 글을 쓸 때 정한 비밀번호를 다시 입력해야만 그 글의 메시지를 수정하거나 글을 삭제할 수 있다. 비밀번호가 틀리면 거부 사유와 남은 시도 횟수를 안내하고, 연속 10회 틀리면 그 글은 5분간 **잠금** 상태가 된다. 화면 하단에는 **개발자 정보**(안한석, 202304248)가 표시된다.

## User Stories

### 작성
1. 방문자로서, 이름·메시지·비밀번호만 입력해 글을 남기고 싶다. 가입 없이 바로 인사를 남길 수 있도록.
2. 방문자로서, 글을 남기면 목록 맨 위에 바로 내 글이 보이길 원한다. 제대로 등록됐는지 알 수 있도록.
3. 방문자로서, 이름을 비워 두면 제출이 거부되고 이유가 입력칸 아래에 보이길 원한다. 무엇을 고쳐야 하는지 알 수 있도록.
4. 방문자로서, 메시지를 비워 두거나 공백만 넣으면 거부되길 원한다. 빈 글이 쌓이지 않도록.
5. 방문자로서, 이름이 20자를 넘으면 거부되고 안내받고 싶다.
6. 방문자로서, 메시지가 500자를 넘으면 거부되고 안내받고 싶다.
7. 방문자로서, 비밀번호가 4자 미만이거나 20자를 넘으면 거부되고 안내받고 싶다.
8. 방문자로서, 입력이 거부되어도 이미 입력한 내용은 지워지지 않길 원한다. 다시 쓰지 않아도 되도록.
9. 방문자로서, 앞뒤 공백은 자동으로 제거되길 원한다. 실수로 넣은 공백 때문에 거부되지 않도록.
10. 방문자로서, 비밀번호 입력칸은 가려져(●●●) 보이길 원한다. 옆 사람이 보지 못하도록.
11. 방문자로서, 제출 버튼을 누른 뒤 처리 중임을 알 수 있길 원한다. 중복 제출하지 않도록.

### 조회
12. 방문자로서, 모든 글을 한 페이지에서 보고 싶다.
13. 방문자로서, 글이 작성 시각 최신순으로 정렬되길 원한다. 새 인사를 먼저 볼 수 있도록.
14. 방문자로서, 각 글의 작성자 이름, 메시지, 작성 시각을 보고 싶다.
15. 방문자로서, 작성 시각이 한국 시간 `YYYY-MM-DD HH:mm` 형식으로 보이길 원한다. 서버 시간대와 상관없이 정확히 읽을 수 있도록.
16. 방문자로서, 메시지의 줄바꿈이 그대로 보이길 원한다.
17. 방문자로서, 메시지에 HTML이나 스크립트를 넣어도 글자 그대로 보이길 원한다. 다른 방문자가 공격받지 않도록.
18. 방문자로서, 글이 하나도 없을 때 "아직 글이 없습니다" 같은 안내를 보고 싶다.
19. 방문자로서, 수정된 글에는 "(수정됨)"과 마지막 수정 시각이 보이길 원한다. 원래 내용이 바뀌었음을 알 수 있도록.
20. 방문자로서, 글이 수정되어도 목록 순서는 바뀌지 않길 원한다. 정렬 기준이 작성 시각이므로.
21. 방문자로서, 휴대폰에서도 목록과 입력 폼을 편하게 쓰고 싶다.

### 수정
22. 글쓴이로서, 내 글의 [수정] 버튼을 누르면 글 카드 안에 메시지 입력칸과 비밀번호 입력칸이 펼쳐지길 원한다. 페이지를 옮기지 않고 고칠 수 있도록.
23. 글쓴이로서, 수정 입력칸에 기존 메시지가 미리 채워져 있길 원한다.
24. 글쓴이로서, 올바른 비밀번호를 입력하면 메시지가 수정되고 목록에 바로 반영되길 원한다.
25. 글쓴이로서, 메시지만 수정할 수 있고 이름과 작성 시각은 그대로이길 원한다.
26. 글쓴이로서, 수정할 메시지도 작성할 때와 같은 규칙(1~500자)으로 검사받길 원한다.
27. 글쓴이로서, 비밀번호가 틀리면 "비밀번호가 일치하지 않습니다. (남은 시도 N회)"가 입력칸 아래에 보이길 원한다.
28. 글쓴이로서, 비밀번호가 틀려도 내가 고쳐 쓴 메시지는 입력칸에 남아 있길 원한다.
29. 글쓴이로서, [취소]를 누르면 입력칸이 접히고 아무것도 바뀌지 않길 원한다.

### 삭제
30. 글쓴이로서, 내 글의 [삭제] 버튼을 누르면 글 카드 안에 비밀번호 입력칸이 펼쳐지길 원한다.
31. 글쓴이로서, 올바른 비밀번호를 입력하면 글이 완전히 삭제되고 목록에서 바로 사라지길 원한다.
32. 글쓴이로서, 비밀번호 입력 자체가 확인 절차이므로 별도의 "정말 삭제할까요?" 창은 뜨지 않길 원한다.
33. 글쓴이로서, 비밀번호가 틀리면 삭제가 거부되고 "비밀번호가 일치하지 않습니다. (남은 시도 N회)"가 보이길 원한다.

### 잠금
34. 글쓴이로서, 남이 내 글의 비밀번호를 무한정 추측하지 못하길 원한다.
35. 방문자로서, 한 글에 비밀번호를 연속 10회 틀리면 "비밀번호를 10회 틀려 잠겼습니다. N분 후 다시 시도하세요."를 보고 싶다.
36. 글쓴이로서, 잠긴 동안에는 올바른 비밀번호도 거부된다는 것을 이해하고, 남은 시간을 안내받고 싶다.
37. 글쓴이로서, 5분이 지나면 다시 수정·삭제를 시도할 수 있고 시도 횟수도 10회로 돌아오길 원한다.
38. 글쓴이로서, 비밀번호를 한 번 맞히면 그전 실패 횟수가 초기화되길 원한다.
39. 방문자로서, 수정 실패와 삭제 실패가 합산되어 세어진다는 것을 남은 시도 횟수로 알 수 있길 원한다.
40. 방문자로서, 한 글이 잠겨도 다른 글의 수정·삭제는 영향을 받지 않길 원한다.

### 기타
41. 방문자로서, 이미 삭제된 글을 수정·삭제하려 하면 "글을 찾을 수 없습니다"라는 안내를 보고 싶다. (다른 탭에서 먼저 삭제한 경우)
42. 채점자로서, 화면 푸터에서 "개발자: 안한석 (202304248)"을 확인하고 싶다.
43. 채점자로서, Vercel 배포 URL에서 작성·조회·수정·삭제가 실제로 동작하는 것을 확인하고 싶다.
44. 운영자로서, DB가 유출되어도 원래 비밀번호는 알 수 없길 원한다.

## Implementation Decisions

- **스택**: Next.js(App Router) + TypeScript, Neon Postgres, Vercel(고정). 그 위에 Tailwind CSS, Drizzle ORM + `@neondatabase/serverless`, Server Actions, Vitest.
- **방명록 모듈 (깊은 모듈 1개)**: 모든 도메인 규칙(입력 검증, 비밀번호 해시·비교, 잠금, 정렬)을 한 모듈에 둔다. 페이지와 Server Actions는 이 모듈을 호출하고 결과를 화면에 옮기기만 한다.
  - `createEntry(input, now)` → 성공 | 입력 오류(필드별 사유)
  - `listEntries()` → 작성 시각 내림차순 글 목록 (비밀번호 해시·실패 기록 칸은 포함하지 않음)
  - `editEntry(id, message, password, now)` → 성공 | 입력 오류 | 비밀번호 불일치(남은 시도) | 잠금(남은 분) | 없음
  - `deleteEntry(id, password, now)` → 성공 | 비밀번호 불일치(남은 시도) | 잠금(남은 분) | 없음
  - 결과는 예외가 아니라 구분된 유니온 값으로 돌려준다. 현재 시각(`now`)과 DB 연결은 주입받는다.
- **스키마**: `entries` 테이블 1개 — id, author_name, message, password_hash, created_at, updated_at(수정 시에만 값), failed_attempts(기본 0), locked_until(nullable). created_at 인덱스.
- **비밀번호**: bcrypt 해시로 저장하고 비교는 서버에서만 한다. 해시는 클라이언트로 절대 내려가지 않는다.
- **입력 검증**: 앞뒤 공백 제거 후 이름 1–20자, 메시지 1–500자, 비밀번호 4–20자. 서버에서 반드시 검사한다(클라이언트 검사는 편의용).
- **잠금 규칙** ([ADR 0001](./adr/0001-글-단위-잠금.md)): 글 단위로 연속 실패를 센다. 수정·삭제 합산. 10회째 실패 시 locked_until = now + 5분. 잠금 중에는 비밀번호를 비교하지 않고 거부. 성공 시, 또는 잠금 시각이 지난 뒤 첫 시도 시 횟수 초기화. 동시 요청에서 횟수가 어긋나지 않도록 증가는 한 번의 UPDATE로 처리한다.
- **시각 표시**: DB에는 timestamptz(UTC)로 저장하고, 화면에서 Asia/Seoul로 변환해 `YYYY-MM-DD HH:mm`으로 표시한다. 남은 잠금 시간은 분 단위 올림.
- **UI**: 단일 페이지. 상단 작성 폼, 그 아래 목록, 하단 푸터(개발자 정보). 수정·삭제는 글 카드 안에서 펼치는 인라인 폼. 변경 후 목록은 경로 재검증으로 갱신.
- **DB 연결**: neon.tech에서 `guestbook-202304248` 프로젝트를 직접 만들고 `DATABASE_URL`을 로컬 `.env.local`과 Vercel 환경변수에 수동으로 넣는다.
- **마이그레이션**: drizzle-kit generate로 마이그레이션 파일을 만들고 migrate로 적용한다. 파일은 저장소에 커밋한다.
- **배포**: GitHub `anhanseok/guestbook--202304248`(public)을 Vercel 프로젝트 `guestbook-202304248`에 연결한다.

## Testing Decisions

- **좋은 테스트의 기준**: 방명록 모듈의 공개 함수만 호출하고, 반환 결과와 이후 `listEntries()`로 보이는 상태만 검증한다. 내부 SQL, 해시 함수 호출 여부, 칸 이름 같은 구현 세부는 검증하지 않는다.
- **테스트 경계는 방명록 모듈 하나**다. Server Actions와 UI는 얇은 전달 계층이라 자동 테스트하지 않고, 배포 URL에서 수동으로 CRUD를 확인한다.
- **DB**: 테스트에서는 PGlite(프로세스 안에서 도는 Postgres)에 같은 마이그레이션을 적용해 쓴다. Neon에 접속하지 않는다.
- **시계**: `now`를 주입해 "10회 실패 → 잠금 → 5분 후 해제"를 기다리지 않고 검증한다.
- **다룰 시나리오**: 작성 성공/필드별 거부, 최신순 정렬, 수정 후 순서 유지와 수정됨 표시, 올바른/틀린 비밀번호의 수정·삭제, 남은 시도 횟수 감소, 10회째 잠금, 잠금 중 올바른 비밀번호 거부, 5분 후 해제와 횟수 초기화, 성공 시 초기화, 수정·삭제 실패 합산, 다른 글은 영향 없음, 없는 글, 목록에 해시가 노출되지 않음.
- **선례**: 저장소가 비어 있어 기존 테스트는 없다. 이 모듈 테스트가 첫 선례가 된다.

## Out of Scope

- 회원가입, 로그인, 관리자 기능
- 작성자 이름 수정, 비밀번호 변경·찾기
- 페이지 나누기, 검색, 좋아요, 댓글
- IP 기준 잠금, 스팸·욕설 필터, CAPTCHA
- 삭제한 글 복구(soft delete)
- 이미지·파일 첨부
- UI 자동 테스트(E2E)
